# Angle niceness

An explorable unit circle: the *niceness* of an angle x = 2πk/n is
D = [ℚ(cos x, sin x) : ℚ] — φ(n)/2 if 4 | n, else φ(n).

**HTML frontend, Lean backend.** All mathematics lives in Lean; the page only
draws SVG and renders KaTeX.

| file | role |
|---|---|
| `AngleNiceness.lean` | the math: exact radical arithmetic (`vsqrt` with denesting, `cosSym`/`sinSym`), cyclotomic polynomials, minimal polynomials of cos, `niceness`. Ends with a `#guard`/theorem test suite — the file compiles iff every test passes. |
| `AngleNicenessSpec.lean` | Mathlib specification layer: `nicenessSpec` via `Nat.totient`; bridges checking the executable code against the spec (`native_decide`), and **unbounded** proofs that niceness is invariant under reflection across the x-axis (x ↦ −x), the y-axis (x ↦ π − x), and the 45° diagonal (x ↦ π/2 − x, swapping cos and sin) — and, by `nicenessSpec_reflections`, under **any finite sequence** of these; plus {0, π/2, π, 3π/2} all have niceness 1. |
| `Gen.lean` | page-data generator: angle table, positions, LaTeX, the step-by-step D derivation trees. |
| `angle-niceness-data.js` | generated by `lake exe gen` — do not edit. |
| `angle-niceness.html` | frontend: slider, SVG, KaTeX rendering of `.ktx` spans. |

## Build

```sh
lake build          # compiles everything = runs all tests and proofs
lake exe gen        # regenerates angle-niceness-data.js
open angle-niceness.html
```

Toolchain: Lean 4.30.0, Mathlib pinned in `lakefile.toml`.

## Complete set (no display cutoff)

The page draws the **complete** set of angles with D ≤ 10, constructed
directly rather than by enumerating denominators to a cutoff: `Dden n ≤ T`
forces `n ≤ 2(2T+1)²` (theorem `denominator_le_of_Dden_le`, from the
elementary bound n ≤ 2·φ(n)²), so a bounded scan provably finds every
qualifying denominator (`mem_completeDens`). Because membership depends only
on D, the set is closed under all D-preserving symmetries — verified by a
`#guard` in `Gen.lean` (closure under x-axis, y-axis and diagonal
reflections; e.g. both 80° = 2π·2/9 and its diagonal mirror 10° = 2π·1/36
are drawn).

## Known representation limits (tested, documented)

- Products of *distinct* nested radicals stay nested (√W·√W′ = √(W·W′));
  equal ones collapse (√W·√W = W).
- For n with odd part 15, cos(2πk/n) is built via the angle-difference formula
  while related angles use the half-angle tower — numerically equal values with
  different radical shapes, so a few exact-identity tests are scoped around
  odd-part-15 and covered numerically instead (see the test section of
  `AngleNiceness.lean`).

## Q&A

Questions asked while building this, with the answers (lightly condensed).

### Why was 80° = 4π/9 (D = 6) drawn but its counterpart 10° = π/18 (also D = 6) missing?

*(Asked when the page still enumerated denominators n ≤ 24.)* Both angles do
have D = 6 — φ(9) = 6 and φ(36)/2 = 6 — so nothing was wrong with D. Two
separate facts explained the picture:

1. 80° → 10° is **not** an x/y-axis reflection: compositions of x ↦ −x and
   x ↦ π − x generate only {x, −x, π−x, π+x}, and that orbit of 80°
   ({80°, 100°, 260°, 280°}) was fully drawn. The symmetry relating 80° and
   10° is the **45° diagonal** x ↦ π/2 − x, which swaps cos ↔ sin (and hence
   trivially preserves ℚ(cos x, sin x)).
2. The diagonal can quadruple the denominator (9 ↦ 36), and 36 > 24 fell
   outside the enumeration cutoff — a display artifact, not a math asymmetry.

This led to the diagonal-invariance theorem `nicenessSpec_diag`, the
any-sequence-of-reflections theorem `nicenessSpec_reflections`, and
ultimately to replacing the cutoff with the complete-set construction, after
which the question can no longer arise.

### Can the complete set be constructed directly, instead of enumerating to a cutoff or closing under reflections?

Yes — invert D. It depends only on the reduced denominator
(Dden n = φ(n)/2 if 4 | n, else φ(n)), and the elementary bound
**n ≤ 2·φ(n)²** (proved in `le_two_mul_totient_sq` by strong induction on the
least prime factor) gives: Dden n ≤ T ⟹ n ≤ 2(2T+1)². So a bounded scan
(`completeDens T`) provably finds *every* qualifying denominator
(`mem_completeDens`), and all reduced k/n over those denominators is the
complete sublevel set {x : D(x) ≤ T}. Symmetry is then automatic: membership
depends only on D, and D is reflection-invariant. The page draws exactly
`completeDens 10` (216 angles).

### Why does 22π/15 (D = 8) have a radical formula while 13π/9 (D = 6) does not?

Because radical-expressibility depends on the **factorization** of the degree,
not its size. Each square root at most doubles a field's degree, so
square-root towers reach exactly the degrees 2^j:

- 22π/15: φ(15) = 8 = 2·2·2 — a tower of quadratic steps exists, and the
  engine builds cos(22π/15) = (1 + √5 − √(30−6√5))/8.
- 13π/9: φ(18) = 6 = 2·**3** — cos is a root of the irreducible cubic
  8t³ − 6t − 1, a degree-3 step no square-root tower can contain (same fact
  as: the regular 18-gon is not constructible). Worse, the cubic has three
  real roots (*casus irreducibilis*), and by Isaacs' theorem a totally real
  irrational whose degree is not a power of 2 has **no real-radical formula
  of any index** — every radical expression must detour through complex
  numbers.

Each point's info panel now carries this argument in its constructibility
footer, specialized to its own n.

### What is the sequence 4, 16, 48, 96, 176, 216 (the "angles visible" counts)? It's not in OEIS.

It is the cumulative count a(T) = Σ φ(n) over denominators with Dden(n) ≤ T,
evaluated at the realized levels T = 1, 2, 4, 6, 8, 10 — equivalently, the
number of torsion points of the unit circle whose coordinates generate a
number field of degree ≤ T:

| cutoff | new denominators n | added | total |
|---|---|---|---|
| D ≤ 1 | 1, 2, 4 | 4 | 4 |
| D ≤ 2 | 3, 6, 8, 12 | 12 | 16 |
| D ≤ 4 | 5, 10, 16, 20, 24 | 32 | 48 |
| D ≤ 6 | 7, 9, 14, 18, 28, 36 | 48 | 96 |
| D ≤ 8 | 15, 30, 32, 40, 48, 60 | 80 | 176 |
| D ≤ 10 | 11, 22, 44 | 40 | 216 |

It is absent from OEIS because it is a cumulative distribution sampled at
irregular thresholds of a bespoke measure (φ halved iff 4 | n), truncated at
the page's MAXD. Structural check: every term ≥ 16 is ≡ 0 (mod 8) — generic
angles come in dihedral orbits of 8, and the only short orbits are the 4
cardinal points (D = 1) and the 4 diagonal points ±π/4, ±3π/4 (D = 2), so
a(T) = 4 + 4 + 8k for T ≥ 2.

### Is it more informative to show nested radicals nested, or denested as radical ± radical?

Denested, whenever it exists — and nesting is kept only when it is forced,
which is itself information:

- Sums c₀ + c₁√r₁ + … over distinct squarefree rᵢ are a **canonical form**
  (Besicovitch independence): equal numbers always look identical. Nested
  radicals have no normal form (equality is genuinely hard to decide).
- √(A+B√m) denests iff A² − B²m is a square, iff the apparent quartic
  collapses into a biquadratic field ℚ(√u, √v) — so the denested form is the
  *proof* of a degree collapse, and it exposes the Galois conjugates (flip
  the signs). Re-nesting is trivial (square it); denesting is the hard
  direction.
- When A² − B²m is not a square, the depth is a genuine property of the
  number, and the engine keeps a minimal nested form.

The mixed output visible on the page — e.g. cos(22π/15) =
(1 + √5 − √(30−6√5))/8 — is therefore maximal information: flat where
flatness is a theorem, nested where depth is a theorem.

### Slider vs +/− stepper for the D cutoff (UX)?

A slider earns its keep for dense ranges (one-gesture scrubbing) and as a
spatial gauge of position-in-range. Here the domain is a 6-element ordered
enum with uneven spacing (so the spatial metaphor lies), touch drags fight
scrolling and overshoot (Fitts's law), and the core interaction is *stepwise*
comparison — "admit the next level, see which color appears." A stepper makes
each press exactly one level (predictable, reversible), with disabled states
marking the bounds; the color legend doubles as a richer range gauge (chips
above the cutoff dim) and as direct random access (click a chip to jump).
Only real loss: the native arrow-key handling a `<input type=range>` gave
for free.
